# Field

## 1. What it is for

A field puts together everything one form value needs: a visible label, the control, a hint and an error, always in the same order and spacing, so forms read the same everywhere.

## 2. When to use

Every value in a form: checkout, order lookup, sign-in and sign-up, the product and category forms, the stock panel, the import. Today these are assembled by hand from `Label`, `<p>` and `FieldError` in `form-feedback.tsx`; they move to `Field` in the retrofit (lesson 08).

## 3. When not to use

| Instead of a field…                  | Use                                                  | Why                                   |
| ------------------------------------ | ---------------------------------------------------- | ------------------------------------- |
| A form-level result ("Order placed") | the form message (`role="status"` or `role="alert"`) | It is about the form, not one value   |
| A search box in the header           | Input with a visible label or icon (frame retrofit)  | The header has its own layout (audit) |
| Read-only data in a details view     | a description list                                   | Nothing to type                       |

## 4. Anatomy

1. `Field`: the wrapper, `--space-related` (8 px) between its parts.
2. `FieldLabel`: always visible; `optional` adds "(optional)".
3. The control: `Input`, `Textarea`, `NativeSelect`, or (horizontal) `Checkbox`, `RadioGroupItem`.
4. `FieldContent` (horizontal only): the label, hint and error next to the control.
5. `FieldDescription` (optional): the hint, `type-small`, `--muted-foreground`.
6. `FieldError` (optional): icon and text in `--destructive`; renders nothing without a message.
7. `FieldGroup`: fields `--space-group-item` apart (16 px store, 12 px admin).
8. `FieldSet` and `FieldLegend` (optional): a named group of fields ("Shipping address").

Order: label, control, hint, error (B1.26).

## 5. Variants

`FieldLegend` has two: `legend` (`type-h3`, a group title) and `label` (looks like a field label, for a group that is one question). `Field` has two orientations: `vertical` (default: label, control, hint, error stacked) and `horizontal` (batch 2, B2.11: a checkbox or radio on the left, `FieldContent` with the label, hint and error on the right; the row is at least `--control-h-sm` tall, 44 px on a phone, and the box sits on the first line of the label through `--choice-offset`).

## 7. Behavior and accessibility

- The control has `id`; `FieldLabel htmlFor` names it; `aria-describedby` lists the hint and the error ids; an error sets `aria-invalid` (WCAG 1.3.1, 3.3.1).
- The error is not a live region: after a submit the form shows one summary with `role="alert"`, and focus moves to the first field with an error (audit decision 5, tokeny.md §7 rule 13). Several alerts at once would be read over each other.
- Values typed before a failed submit stay in the fields.
- `Field` is a `role="group"`; `FieldSet` is a `<fieldset>` named by its `<legend>`.

## 8. Content

- Label: a noun ("Postal code"). Hint: the format or the rule ("For example 249.90 or 249,90."). Error: what happened and what to do ("Enter a postal code like 00-950."), never "Invalid value" (Content page, R03.3).
- Several messages for one field are joined into one sentence list.
- Long hints and errors wrap; the error icon stays on the first line.

## 9. Responsive

- 320 px: one column, full width.
- 768 and 1440 px: the form keeps a readable width (`max-w-sm` to `--measure-prose`); a group may use two columns (city and postal code).

## 10. API

| Part               | Props                                                                                             | Default      |
| ------------------ | ------------------------------------------------------------------------------------------------- | ------------ |
| `Field`            | `<div>` props; `orientation?: "vertical" \| "horizontal"`; `data-disabled="true"` greys the label | `"vertical"` |
| `FieldContent`     | `<div>` props; label, hint and error of a horizontal field                                        | –            |
| `FieldLabel`       | `<label>` props; `optional?: boolean` adds "(optional)"                                           | `false`      |
| `FieldDescription` | `<p>` props; give it an `id` for `aria-describedby`                                               | –            |
| `FieldError`       | `<p>` props; `children` = the message, nothing rendered when empty                                | –            |
| `FieldGroup`       | `<div>` props                                                                                     | –            |
| `FieldSet`         | `<fieldset>` props                                                                                | –            |
| `FieldLegend`      | `<legend>` props; `variant?: "legend" \| "label"`                                                 | `"legend"`   |

## 11. Code

```tsx
import { Field, FieldDescription, FieldError, FieldLabel } from "@/components/ui/field";

<Field>
  <FieldLabel htmlFor="product-sku" optional>
    SKU
  </FieldLabel>
  <Input id="product-sku" name="sku" aria-describedby="product-sku-hint" />
  <FieldDescription id="product-sku-hint">
    Saved in capitals, for example DEMO-MOU-001.
  </FieldDescription>
</Field>;
```

```tsx
// Checkout field with a server error (fieldA11y builds aria-invalid and aria-describedby).
<Field>
  <FieldLabel htmlFor="shippingPostalCode">Postal code</FieldLabel>
  <Input id="shippingPostalCode" name="shippingPostalCode" {...fieldA11y(errorId, errors)} />
  <FieldError id={errorId}>{errors?.join(" ")}</FieldError>
</Field>
```
