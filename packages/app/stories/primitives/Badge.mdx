# Badge

## 1. What it is for

Showing the status of one thing (an order, a product, a recommendation) in a word or two, so the user can scan a list and see what needs attention.

## 2. When to use

- Admin: order status and the DEMO mark in the order list and details; product availability and "Featured"; the outcome of each row in the CSV import preview; Copilot priority, recommendation status and the demo traffic tag; system status on the dashboard.
- Store: availability on the product card and page ("In stock"); the order status on the demo payment and confirmation pages.
- On a product photo: at most 1–2 badges (R03.4, rule 6).

## 3. When not to use

| Instead of a badge…                     | Use                                 | Why                                        |
| --------------------------------------- | ----------------------------------- | ------------------------------------------ |
| Something the user can click            | `TextLink` or Button                | A badge is not interactive (B2.15)         |
| A message with a sentence and an action | Alert                               | A badge holds 1–3 words                    |
| A count on the cart                     | the cart counter (frame, lesson 08) | The only pill shape (P4)                   |
| Decoration or marketing ("Hot", "-20%") | nothing                             | A01: a stack of labels on a photo is noise |
| A price                                 | plain text, `--foreground`          | Prices are never colored (rule 1)          |

## 4. Anatomy

1. Container: 4 px radius (`--radius-badge`, P4), 2 px from the text to the edge (1 px border + 1 px padding, the one exception to the 4 px grid), 8 px inline padding.
2. Text: the `small` style, 500 (14/20 px store, 12/16 px admin); one line, never wraps.
3. Icon (optional): 16 px Tabler icon before the text; the text stays.

Height: 24 px in the store, 20 px in the admin.

| `default`     | `--primary` fill (16.98 / 15.50 : 1)                         | the strongest neutral mark: "Featured"                               |
| `secondary`   | `--secondary` fill (15.57 / 14.74 : 1)                       | a neutral, ongoing status: "Processing"                              |

### How to choose: status → variant (applied to the screens in the retrofit, lesson 08)

| Where         | Status → variant                                                                                                                  | Source                  |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| Orders        | pending_payment `warning`, paid `success`, processing `secondary`, shipped `outline`, cancelled `destructive`, refunded `outline` | P2 (approved)           |
| Demo data     | DEMO order, demo traffic in Copilot → `demo`                                                                                      | rule 11, P3             |
| Availability  | In stock `success`, Low stock `warning`, Out of stock `outline`, Hidden `outline`                                                 | tokeny.md §1b; proposal |
| Product       | Featured `default`, Published `success`                                                                                           | tokeny.md §1b           |
| CSV import    | create `success`, skip `outline`, error `destructive`                                                                             | proposal                |
| Copilot       | priority high `warning` (not red: red means an error, rule 5), medium and low `secondary`                                         | proposal, rule 20       |
| System status | up `success`, down `destructive`                                                                                                  | proposal                |

## 6. States

A badge has no interactive states: no hover, focus, pressed, disabled, loading, selected or error (B2.15). If a screen renders it as a link through `render`, it gets the standard focus outline, but use a `TextLink` instead.

## 7. Behavior and accessibility

- Plain text in a `<span>`: screen readers read the words, so the status is never color alone (WCAG 1.4.1, rule 10).
- Text contrast is at least 5.70 : 1 in both themes (pairs 14, 20, 26, 29, 30).
- Next to a name in a table, keep the badge after the name, so the row reads "CO-GWP9H, Paid".
- Not a target; no minimum size applies.

## 8. Content

- 1–3 words in sentence case, the same word everywhere for the same status (`ORDER_STATUS_LABELS`).
- Statuses say a fact the product has (R03.3): "Pending payment", not "Hurry".
- Numbers only when they are the status ("3 left" is not used: shoppers never see exact stock).
- Longer languages: badges stay one line; a row of badges wraps as a whole.

## 9. Responsive

- 320 px: a row of badges wraps between badges, never inside one.
- 768 and 1440 px: no change.

## 11. Code

```tsx
import { Badge } from "@/components/ui/badge";

<Badge variant="success">Paid</Badge>;
```

```tsx
// Order status (retrofit): one map from the status to the variant.
const STATUS_VARIANTS = {
  pending_payment: "warning",
  paid: "success",
  processing: "secondary",
  shipped: "outline",
  cancelled: "destructive",
  refunded: "outline",
} as const;

<Badge variant={STATUS_VARIANTS[order.status]}>{ORDER_STATUS_LABELS[order.status]}</Badge>;
```
