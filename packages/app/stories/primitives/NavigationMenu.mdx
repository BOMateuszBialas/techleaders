# Navigation menu (megamenu)

## 1. What it is for

Getting from the store header to any category in one step: one "Shop" item opens a panel with "Shop all" and every category, each with its one-line description.

## 2. When to use

- The store header on screens from 768 px (owner change to Q1, B4.21–B4.32), once the header is retrofitted.
- A top-level header item whose children are pages (categories). Every item in the panel is a link.

On phones the same links sit in the [Disclosure](?path=/docs/primitives-disclosure--docs) "Menu" (batch 3), which works without JavaScript (spec G13).

## 3. When not to use

| Instead of a navigation menu…                 | Use                                        | Why                                                                             |
| --------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------- |
| Actions on an object (edit, delete)           | buttons on the details page (R04.1)        | Navigation menus hold links; an action menu has role `menu` ("What is missing") |
| Two or three top-level links without children | plain links (`navigationMenuTriggerStyle`) | Nothing to open                                                                 |
| The phone header                              | Disclosure                                 | Works without JavaScript and pushes the content down                            |
| Promotions, banners or product tiles          | the home page                              | A wall of promotions in the menu is anti-reference A01                          |
| Filters on the listing                        | the catalog search form                    | Filters change the current page, not the place                                  |

## 4. Anatomy

1. Root: `<nav>` with a name ("Main").
2. List and item: the top-level row.
3. Trigger: a link to the catalog (`href`) that, with JavaScript, opens the panel instead; text and focus outline in the header's text color; a chevron that turns 180° when open.
4. Panel: `--popover` surface, `--border` outline, the overlay shadow, 12 px radius, 16 px padding (`--space-group-item`), 8 px under the trigger, `z-50`, no backdrop.
5. "Shop all": the first link, full width, with an arrow.
6. Grid: categories in 2 columns, 3 from `lg`; each link is the name (`body`, 600) and the description (`small`, `--muted-foreground`).

Removed from the base (B4.31): the indicator arrow, nested submenus and the sliding animation between items.

## 7. Behavior and accessibility

- **Without JavaScript** the trigger is a plain link to `/products` (no button role, no expanded state in the server HTML), and the category links are in the page source, hidden. Nobody is stuck (spec G13).
- With JavaScript the trigger becomes a button with `aria-expanded`: a click, Enter, Space or ArrowDown opens the panel; Ctrl, Cmd, Shift or middle click still open the catalog in a new tab.
- Hover opens after a 200 ms intent delay and closes 300 ms after the pointer leaves. Base UI keeps a safe triangle from the trigger to the panel and ignores hover on touch. The panel can be hovered, closed with Escape and stays until the pointer or focus leaves (WCAG 1.4.13).
- Tab moves from the trigger into the panel; Escape closes and returns focus to the trigger; moving focus out closes it.
- Each link closes the panel when followed.

## 8. Content

- Trigger: one short word that names the place ("Shop"), never "Menu" or an icon alone.
- Links: the category name as in the catalog; the description is the category's own one-liner from the data, with the `[DEMO]` marker kept (AGENTS.md principle 6).
- No counts, prices or promotions in the panel.

## 9. Responsive

- Below 768 px: not shown; the header shows the Disclosure menu.
- 768–1023 px: 2 columns. From 1024 px: 3 columns, at most 48 rem wide; the panel never leaves the window (16 px collision padding).
- Long category names wrap inside their 240 px column.

## 10. API

<ArgTypes of={NavigationMenuStories} />

Parts: `NavigationMenu` (Base UI `Root` with the positioner, popup and viewport built in; `delay` 200, `closeDelay` 300, `align`), `NavigationMenuList`, `NavigationMenuItem`, `NavigationMenuTrigger` (**required `href`**), `NavigationMenuContent` (`keepMounted` by default), `NavigationMenuGrid`, `NavigationMenuLink` (`href`, `description`, `active`), `navigationMenuTriggerStyle`.

## 11. Code

```tsx
import {
  NavigationMenu,
  NavigationMenuContent,
  NavigationMenuGrid,
  NavigationMenuItem,
  NavigationMenuLink,
  NavigationMenuList,
  NavigationMenuTrigger,
} from "@/components/ui/navigation-menu";

<NavigationMenu aria-label="Main" className="hidden md:flex">
  <NavigationMenuList>
    <NavigationMenuItem>
      <NavigationMenuTrigger href={productsHref()}>Shop</NavigationMenuTrigger>
      <NavigationMenuContent>
        <NavigationMenuLink href={productsHref()} className="w-full">
          Shop all
        </NavigationMenuLink>
        <NavigationMenuGrid>
          {categories.map((category) => (
            <li key={category.slug}>
              <NavigationMenuLink
                href={productsHref(category.slug)}
                description={category.description}
                active={category.slug === currentSlug}
              >
                {category.name}
              </NavigationMenuLink>
            </li>
          ))}
        </NavigationMenuGrid>
      </NavigationMenuContent>
    </NavigationMenuItem>
  </NavigationMenuList>
</NavigationMenu>;
```

## 13. Related

- **Disclosure**: the phone menu.
- **Text link**: links in content and the footer category list.
- **Dialog**: never for navigation.
- "What is missing": Menu (actions, role `menu`), nested submenus, a panel per category (when categories get children, Q8).
