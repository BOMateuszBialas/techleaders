# Epic E04: Orders and dashboard for the owner

Backlog epic E04 (issue #11): stories E04-S01 (list orders, open one, move it through the status workflow), E04-S02 (a dashboard of real metrics with visible definitions), E04-S03 (a populated, clearly labelled demo store on first run). The owner reads tables and figures here, so the rules are density, neutral color, and definitions on the page.

## Flow

1. The owner opens the dashboard (`/admin`) and reads the metrics for a period: 7 days, 30 days, or a custom range of whole days.
2. Each metric shows its definition as visible text (orders spec A8). AOV says "Not enough data" when there are no paid orders.
3. The owner opens the orders list (`/admin/orders`) and an order (`/admin/orders/[id]`).
4. The order shows its items (name and price as they were sold), its total and its status.
5. The owner changes the status only along the workflow. The next states offered are the ones the rules allow; a status with none says "No further status changes."
6. Cancelling an unpaid order returns its stock. Refunding records the status only: no money moves (demo store).
7. Demo data is labelled: `DEMO-` order references and `[DEMO]` products. The seed creates no unpaid order (orders spec A15), so the seeded list starts without one.

## Rules this epic follows

- Metric definitions are visible text next to each figure, never behind a hover (orders spec A8, batch 4 Q2). The Copilot uses the same definitions (AGENTS.md metric rule).
- The admin never shows the purchase red. Status badges use text and their variant; the main button is graphite (tokeny §7 rule 4, P2).
- Numbers are right-aligned with tabular figures; a table cell does not wrap a number (tokeny §3, B3.5).
- The dashboard shows order and stock metrics; the demo traffic figures belong to the Copilot and are labelled "(demo)" (orders spec A12).
- Refund and cancel move no money: the refund is a status record only, and the cancel restocks a pending order in one transaction (AGENTS.md).

## Retrofit (lesson 08)

1. `Card` for each metric, the definition printed under it, `Skeleton` in one labelled group.
2. `TabsNav` with `TabsNavLink` for the period, so the links keep working without JavaScript (batch 3 Q1).
3. `Table` for the orders list with the status as `Badge` text and the totals right-aligned.
4. `AlertDialog` for cancel and refund instead of the checkbox (batch 4 Q5); the hidden `confirm=yes` field stays.
5. `Empty` for the empty states with the next step; `Alert` for the range fallback and the status results.
