# Epic E03: Owner access and catalog management

Backlog epic E03 (issue #10): stories E03-S01 (owner sign-in, only owners reach admin pages), E03-S02 (products and categories, with what each change affects), E03-S03 (manual stock adjustment and its effect on availability). The admin is dense and neutral (K7, R04.1, R04.2): graphite main button, color only for status, links and errors, no purchase red.

## Flow

1. The owner signs in at `/admin/sign-in`. Every admin page checks the session on the server; a missing session goes to sign-in.
2. The owner lists products and categories, and opens one to edit it, or creates a new one.
3. A product form saves name, slug, price, category, description and "Featured on home page". A published product's slug is its store address, so the form warns before a change (G5).
4. The owner can draft a description with AI. The draft is shown as "AI draft, not saved" and replaces the description only when the owner chooses "Replace description with this draft". "Undo" and "Discard" stay available (AI advises, the owner decides).
5. Publish and unpublish is one button on the product page. The outcome is stated next to it.
6. The stock panel sets a new quantity with "Set stock"; the history below lists each change. A product edit never changes the stock; the stock moves only through this panel, a checkout, or the restock of a cancelled unpaid order (database conventions in AGENTS.md).
7. Categories: list, create, edit. Deleting a category asks first; the confirmation says how many products use it.
8. Products can be imported from a CSV file: the file is checked, a preview shows the rows, and only then "Importing…" runs. New products only; a row that matches an existing slug or SKU is skipped.

## Rules this epic follows

- Admin buttons are graphite (`default`); "Delete category" is `destructive`, red text and outline, never filled (tokeny §7 rule 5).
- The admin never shows the purchase red (`action`) (tokeny §7 rule 4). Red appears only as an error or a destructive confirmation.
- The "Featured" checkbox is a `Checkbox` in a horizontal `Field`, saved with the form (batch 2 Q2).
- The publish control is a button that states its outcome, not a switch (batch 2 decisions; see What is missing).
- Warnings (slug, draft) use `--warning`, demo data uses `--demo`; the colors are never mixed (tokeny rule 11).
- Every admin page is guarded on the server; hiding a link is not authorisation (AGENTS.md).

## Retrofit (lesson 08)

1. Product form and category form on `Field`, with `FieldError` and focus on the first invalid field (audit, decision 5).
2. `Checkbox` for "Featured on home page" with its hint; `NativeSelect` for the category.
3. `AlertDialog` for category deletion, with the name in the title and "Cancel" first (batch 4 Q6).
4. `Table` for lists with right-aligned numbers and the status as `Badge` text.
5. `Empty` for the empty lists; `ErrorState` for `error.tsx`; `Skeleton` in one labelled group for the admin loading states (today "Loading orders…" text, audit).
6. The sidebar marks the current page with `aria-current="page"`; today it does not (audit, admin navigation).
