# What to avoid

Three parts. Each item says how to recognise it in the code, why it is wrong for CommerceOS, and what to use instead. The first part is the anti-reference A01 (AceGear, a promotional wall of colour, accepted by the owner as the picture of "overloaded, hard to read"). The second is the generic look the audit found in the app today. The third is implementation mistakes that the tokens and the components already prevent.

Each recognition hint is a plain text search in `packages/app/src` (or the output of `npm run check:tokens`, which lists every palette class, colour literal and arbitrary value with its file and line).

## 1. Anti-reference A01

| #   | Pattern                                                                                 | How to recognise it                                           | Why it is wrong here                                                   | Use instead                                                                                 |
| --- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1   | The action colour used as text (price, percentage) below 4.5 : 1                        | a price or discount in `text-action`, `text-red-*`            | the price must be readable and is not an action (R03.1, tokeny rule 1) | `--foreground`, tabular numbers (`tabular-nums`), weight 600                                |
| 2   | One colour in more than three roles at once (button, price, section background, banner) | the same accent in a button, a badge and a section background | nothing stands out when everything is the same colour (A01, K1)        | red only on the buying step; neutral everywhere else (tokeny rule 2)                        |
| 3   | Gradients in banners, backgrounds or buttons                                            | `bg-gradient-*`, `from-*` with `to-*`                         | decoration with no fact behind it (A01 signature 3)                    | a flat surface token (`--surface-product`, `--muted`)                                       |
| 4   | A shadow on every card                                                                  | `shadow`, `shadow-md` on `Card` or a tile                     | 100+ shadows on one page (A01 signature 4)                             | a border or a tone change; `--shadow-card` is `none` (tokeny rule 8)                        |
| 5   | Two sans families in the UI, text below 12 px                                           | a second font class, `text-[10px]`, `text-xs` on body text    | the reader loses the hierarchy (A01 signature 5)                       | one family (`--font-sans`), six named text styles (`type-*`), 12 px minimum (tokeny rule 9) |
| 6   | Two or more marketing labels on a product photo                                         | several coloured tags over an image                           | the label stack hides the product (A01 signature 6, R03.4)             | at most one or two neutral labels, status as text (tokeny rule 6)                           |
| 7   | A hero made of banners in different palettes                                            | a carousel of unrelated colour blocks                         | the first screen says nothing about the product (A01 signature 7, K6)  | a short hero with the category links right under it (K6)                                    |

## 2. The generic look (audit, step 1)

The audit found that the app is a default shadcn theme with a palette accent from the illustrations. These are the marks of a generic look, with the state found in the code.

| Mark                                                       | How to recognise it                                            | State today                                                                                                    | Why it is wrong here                                               | Use instead                                                                                   |
| ---------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Indigo or purple as the accent without a reason            | `indigo-*`, `purple-*`, `violet-*` in colours or illustrations | the illustrations use purple and indigo (audit: `public/demo/products/*.svg`); the action colour is near-black | the accent has no tie to the brand (D10)                           | one palette for the illustrations (tokeny P10) and the action token                           |
| Card inside a card                                         | a bordered tile inside a bordered card                         | the product card holds a bordered image tile, and the SVG draws a third frame                                  | three layers say the same thing (audit)                            | one surface per card: the image goes to the card edge on `--surface-product` (tokeny rule 7)  |
| Emoji or a text symbol in place of an icon                 | `☰`, emoji in JSX                                             | the mobile menu button uses `☰` (`header-menu.tsx`)                                                           | a symbol is not an icon and its size and weight are not controlled | a Tabler icon at 16 or 20 px (tokeny §6)                                                      |
| A row of big numbers with no definition                    | four `text-2xl` figures                                        | the dashboard metric cards; today each has its definition printed under it (justified by the product)          | a number without its meaning looks like a claim                    | keep the definition visible next to each figure (batch 4 Q2)                                  |
| Pills everywhere                                           | `rounded-full` or `rounded-4xl` on every element               | badges and the cart count                                                                                      | two shape languages with no rule (audit)                           | 4 px for badges, 8 px for controls, 12 px for cards; pill only for the cart count (tokeny P4) |
| Dark navy glow, gradient text, sparkle or wand icon for AI | `Sparkle`, `Wand`, `Bot` icons, text gradients                 | none found (audit)                                                                                             | the Copilot is a tool, not a magic effect (tokeny rule 20)         | a neutral card with the evidence and the actions                                              |

## 3. Implementation mistakes

| Mistake                                          | How to recognise it                                                               | Why it is wrong                                                                                                             | Use instead                                                                                        |
| ------------------------------------------------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Disabled state through opacity                   | `opacity-50`, `disabled:opacity-*`, `bg-primary/80`                               | the colour changes meaning and loses contrast (tokeny rule 14, B1.5)                                                        | `bg-muted text-muted-foreground`, `cursor-not-allowed`, the reason next to the control (tokeny P5) |
| Hover through transparency                       | `hover:bg-*/80`                                                                   | same reason as above                                                                                                        | `--primary-hover`, `--action-hover`, `--accent` (tokeny P7)                                        |
| Dark mode in components                          | `dark:` variants inside a component file                                          | the token file already carries the dark values (B1.11, tokeny rule 19)                                                      | change the token value, check its contrast in both themes                                          |
| Palette classes and arbitrary values             | `text-amber-700`, `text-[0.8rem]`, `p-[13px]`                                     | bypass the tokens (audit, step 3)                                                                                           | a token or a named style; `npm run check:tokens` lists each one                                    |
| Focus that is not visible                        | `outline-none` with no `focus-visible:outline-solid`; `ring-ring/50`              | in Tailwind v4 `outline-none` removes the outline that `outline-2` would draw (WCAG 2.4.7)                                  | `focus-visible:outline-2 outline-offset-2 outline-ring` (B1.4)                                     |
| Clickable `div`                                  | `<div onClick>`                                                                   | not focusable, no role, no keyboard (WCAG 2.1.1)                                                                            | a `<button>`, or an `<a href>` for navigation                                                      |
| Positive `tabIndex`                              | `tabIndex={1}` and up                                                             | it changes the tab order away from the visual order (WCAG 2.4.3)                                                            | no `tabIndex`, or `0` for a scrollable region                                                      |
| `role="alert"` on every field                    | `role="alert"` in a `FieldError` loop, or on a standing note                      | every field error is read at once; a note is announced on each visit (B1.23, B2.18)                                         | `FieldError` without a role; one `role="alert"` per form error, no role for a note                 |
| Placeholder as the label                         | an `<Input placeholder="Search">` with no `FieldLabel`                            | the field loses its name once typed in (audit: the header search at 320 px)                                                 | a visible `FieldLabel`, or a labelled icon button                                                  |
| Error as a toast                                 | a message that disappears after a few seconds                                     | the user may miss an error they must act on (**P**)                                                                         | `FieldError`, an Alert or an Error state                                                           |
| Animated loading loops                           | `animate-spin` on a spinner, a loading dot animation                              | no loops except the skeleton pulse (tokeny §5, batch 3)                                                                     | a `Skeleton` in a labelled `SkeletonGroup`, or `aria-busy` on the button                           |
| Changing the look of a `ui/` component with `cn` | a `className` that sets `rounded-card` on a component that sets `rounded-control` | `cn` does not merge the project's token classes, so both stay and the stylesheet order decides (**P**, implementation note) | check the computed style in a story, or change the token in the component                          |
| Money as a float                                 | `price * 1.23`, `Number(priceText)`                                               | rounding errors and display drift (AGENTS.md, Money)                                                                        | integer minor units and the `Money` helpers; `formatMoney` for display only                        |
| A computed price shown as final                  | a client-side total with no "confirmed at checkout" note                          | the server decides prices (AGENTS.md, Security)                                                                             | show the server's value and "Prices are confirmed at checkout."                                    |
