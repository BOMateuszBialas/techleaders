# Start here: how to build a screen

This Storybook is the manual of the CommerceOS design system: a single-store shop for gaming accessories (decision D10) with a storefront for shoppers and an admin for the store owner. It is written for three readers: a developer building a screen, an AI agent building a screen, and a reviewer checking that a screen follows the system. The short version for agents is [`docs/design-system.md`](https://github.com/BOMateuszBialas/techleaders/blob/main/docs/design-system.md) in the repository.

## Character

**Words: bold, concrete. Never: hard to read, overloaded** (`referencje.md`, confirmed by the owner).

1. The store is a light, readable shop inside a dark brand frame, with one red color reserved for buying (R02.1, R03.1, tokeny rule 18).
2. Headings are large and tight, the text around them is calm, and every number on screen is a fact the product has: price, stock, order status, a demo label (R03.3, K5, tokeny rule 17).
3. The admin is dense and neutral like a resource tool: a dark side menu, tables to scan, a graphite main button and color only where it means something (R04.1, R04.2, K7, tokeny rule 4).

## Five steps to build a screen

| Step                      | What you do                                                                                                                                                                                                                       | Where it is decided                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Find the pattern       | Name the screen's job: a form, a list with filters, a detail view, a delete confirmation. Copy the structure of the same screen type on the epic pages. Shared patterns (form, list, detail, confirmation) are built in lesson 08 | Epic pages (E01–E05, E07), [What is missing](?path=/docs/design-system-what-is-missing--docs)                                          |
| 2. Choose the components  | Choose by what the control does, not by how it looks: a link navigates, a button acts; an error that needs action is never a toast                                                                                                | [How to choose](?path=/docs/design-system-how-to-choose--docs)                                                                         |
| 3. Use semantic tokens    | Colors, spacing, radius, type and heights come from named tokens (`bg-action`, `gap-related`, `rounded-card`, `type-h2`, `h-control-md`). The admin layout sets `data-density="admin"`                                            | Foundations pages, `globals.css`, `tokeny.md`                                                                                          |
| 4. Design the data states | Loading (skeleton in one labelled group), empty (why it is empty and the next step), error (what happened and what to do), long text at 320 px, demo data labelled                                                                | [Usage and accessibility](?path=/docs/design-system-usage-and-accessibility--docs), [Content](?path=/docs/design-system-content--docs) |
| 5. Check what to avoid    | Run `npm run check:tokens`, look for the anti-patterns, check both themes and both densities                                                                                                                                      | [What to avoid](?path=/docs/design-system-what-to-avoid--docs)                                                                         |

## All components

21 components, all in `packages/app/src/components/ui/` and imported as `@/components/ui/<file>`. Each has a page with 13 sections under **Primitives**; the [Components](?path=/docs/design-system-components--components) page shows them live.

| Component       | Import                                                                                                                                                                                                             | When to use                                                                                                                 | When not to use                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Button          | `Button`, `buttonVariants` from `ui/button`                                                                                                                                                                        | an action on this screen; `action` (red) only for a purchase step: Add to cart, Checkout, Place order, Confirm demo payment | navigation (Text link); a red button in the admin or on the dark frame (tokeny §7 rules 2–4)        |
| Text link       | `TextLink`, `textLinkVariants` from `ui/text-link`                                                                                                                                                                 | going to another page (`inline`, `standalone`); a resource name in an admin table (`resource`)                              | an action (Button); a status (Badge)                                                                |
| Input           | `Input` from `ui/input`                                                                                                                                                                                            | one line of text: name, email, quantity, search                                                                             | several lines (Textarea); a choice from a list (Select, Radio group)                                |
| Textarea        | `Textarea` from `ui/textarea`                                                                                                                                                                                      | several lines: product description, a question to Copilot                                                                   | one line (Input)                                                                                    |
| Label           | `Label` from `ui/label`                                                                                                                                                                                            | the visible name of a single control outside a form layout                                                                  | inside a form (use `FieldLabel`); as a heading                                                      |
| Field           | `Field`, `FieldLabel`, `FieldDescription`, `FieldError`, `FieldGroup`, `FieldSet`, `FieldLegend`, `FieldContent` from `ui/field`                                                                                   | every form control: label, control, hint, error in this order (audit decision 5)                                            | a form-level message (Alert); a page error (Error state)                                            |
| Select          | `NativeSelect`, `NativeSelectOption`, `NativeSelectOptGroup` from `ui/native-select`                                                                                                                               | one choice from a longer list, such as the product category in the admin form (owner decision Q1, batch 2)                  | two to five visible options (Radio group); an on/off (Checkbox)                                     |
| Checkbox        | `Checkbox` from `ui/checkbox`, in a horizontal `Field`                                                                                                                                                             | an on/off value saved with the form ("Featured on home page")                                                               | an immediate setting (see What is missing: Switch); one of several (Radio group)                    |
| Radio group     | `RadioGroup`, `RadioGroupItem` from `ui/radio-group`                                                                                                                                                               | one choice from two to five options that must all be visible                                                                | a long list (Select); the theme switch (stays native, spec A5, batch 2 Q3)                          |
| Badge           | `Badge` from `ui/badge`                                                                                                                                                                                            | a status in words: order status, availability, DEMO (P2, P3)                                                                | a link or a button (never clickable, B2.15); more than one or two on a product photo (R03.4)        |
| Alert           | `Alert`, `AlertTitle`, `AlertDescription` from `ui/alert`                                                                                                                                                          | a message about a page or a form: info, success, warning, error (`destructive`), demo                                       | a field error (FieldError); a failed page load (Error state)                                        |
| Card            | `Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardAction`, `CardContent`, `CardFooter` from `ui/card`                                                                                                     | one topic in a panel: a dashboard metric, a sign-in form                                                                    | the product tile (one `--surface-product` surface, B2.29); a card inside a card (audit)             |
| Table           | `Table`, `TableHeader`, `TableBody`, `TableRow`, `TableHead`, `TableCell`, `TableCaption`, `TableFooter` from `ui/table`                                                                                           | records to scan and compare: admin lists, "My orders", Copilot evidence                                                     | product browsing (product tiles); layout                                                            |
| Tabs            | `Tabs`, `TabsList`, `TabsTrigger`, `TabsContent` for panels on one page; `TabsNav`, `TabsNavLink` for views that change the URL                                                                                    | panels of the same object on the same page; views by address (B3.11, Q1 batch 3)                                            | steps of a flow (separate pages); a category filter (filter links, P4)                              |
| Skeleton        | `Skeleton`, `SkeletonGroup` from `ui/skeleton`                                                                                                                                                                     | every `<Suspense>` fallback, inside one `SkeletonGroup` with a label                                                        | a spinner, or "Loading…" text alone (audit decision 5; batch 3 decisions: no spinner)               |
| Empty state     | `Empty`, `EmptyHeader`, `EmptyTitle`, `EmptyDescription`, `EmptyContent` from `ui/empty`                                                                                                                           | nothing here yet, no results for a search or filter, "not found" pages                                                      | an error (Error state)                                                                              |
| Error state     | `ErrorState` from `ui/error-state`                                                                                                                                                                                 | a page or section that failed to load                                                                                       | a field error (FieldError), an error after a form submit (Alert), the Copilot fallback (Alert info) |
| Disclosure      | `Disclosure`, `DisclosureTrigger`, `DisclosureContent` from `ui/disclosure`                                                                                                                                        | extra content behind a summary line; the store menu on a phone (works without JS, storefront spec G13)                      | information needed for the decision: price, error, metric definition (orders spec A8)               |
| Dialog          | `Dialog`, `DialogTrigger`, `DialogContent`, `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogBody`, `DialogFooter`, `DialogClose` from `ui/dialog`                                                       | a short task on top of the page that can be left at any time (batch 4 Q3)                                                   | a confirmation (Alert dialog); a long form or anything worth a URL (a page, R04.1)                  |
| Alert dialog    | `AlertDialog`, `AlertDialogTrigger`, `AlertDialogContent`, `AlertDialogHeader`, `AlertDialogTitle`, `AlertDialogDescription`, `AlertDialogFooter`, `AlertDialogCancel`, `AlertDialogAction` from `ui/alert-dialog` | confirming what cannot be undone: delete a category, cancel an order (batch 4 Q5, Q6)                                       | a reversible action; "Are you sure?" on every save                                                  |
| Navigation menu | `NavigationMenu`, `NavigationMenuList`, `NavigationMenuItem`, `NavigationMenuTrigger`, `NavigationMenuContent`, `NavigationMenuGrid`, `NavigationMenuLink` from `ui/navigation-menu`                               | the store's category megamenu from 768 px (batch 4 Q8–Q12)                                                                  | below 768 px (Disclosure); actions (there is no action menu, see What is missing)                   |

## How the system is organized

| Section       | What is there                                                                                                                                               |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Design system | this page, the component catalog, the rules (How to choose, Usage and accessibility, Content, What to avoid), What is missing, Contributing, the epic pages |
| Foundations   | colors with contrast in both themes, typography, spacing and layout, shape and depth, motion, icons, themes                                                 |
| Primitives    | 21 components, each with 13 sections, a state matrix and interaction tests                                                                                  |
| Product       | not yet: product components (product tile, cart line, order status form, Copilot card) are built in lesson 08                                               |
| Patterns      | not yet: form, list with filters, detail view and delete confirmation are built in lesson 08                                                                |

The toolbar switches **Theme** (light, dark) and **Density** (store, admin). Both go on `<html>`, like in the app, so dialogs and menus get them too (spec A4).

Sources in brackets point to the design records in the repository: `R01–R04`, `A01`, `K1–K7` in `.ai/design/referencje.md`; `P1–P15` and rules 1–20 in `.ai/design/tokeny.md`; `B1.x–B4.x` and `Q` decisions in `.ai/design/POSTEP.md`; "audit" is `.ai/design/audyt.md`; spec letters (A, G) are in `.ai/specs/`. A rule marked **P** has no source yet and is listed in the P list on the [What is missing](?path=/docs/design-system-what-is-missing--docs) page for the owner to decide.
