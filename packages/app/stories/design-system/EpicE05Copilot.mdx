# Epic E05: Commerce Copilot

Backlog epic E05 (issue #12): stories E05-S01 (up to three grounded, prioritised recommendations), E05-S02 (save, dismiss or complete a recommendation, recorded), E05-S03 (an explicit fallback when the AI provider is unavailable), E05-S04 (traffic, funnel and views-without-sales questions from fictional demo data). Copilot advises; the owner decides (AGENTS.md principle 3). Its screens follow the admin rules: neutral cards, priority as text, no AI decoration (tokeny rule 20).

## Flow

1. The owner opens `/admin/copilot`, reads the advisory text ("Copilot suggests; you decide…") and asks a question, or picks a suggested question.
2. While the answer loads, the status reads "Analysing your store data…".
3. The answer gives a short summary with its figures, then up to three recommendations. Each has a title, a priority word ("High priority", "Medium priority", "Low priority"), what was observed, the evidence from the store's data, the reasoning, a suggested action and, where it applies, the products it concerns.
4. The owner saves a recommendation ("Save"), dismisses it ("Dismiss") or marks it done ("Mark completed"). The same card can appear in the answer and under "Your recommendations"; both show the same status.
5. If the AI provider cannot answer, the owner gets the rule-based insights with the reason, and the page says so. It never shows an invented answer.
6. Traffic answers carry the tag "Fictional demo data" and say that the figures are demo figures.

## Rules this epic follows

- The answer never changes the store: no price, product, refund or order is touched by a recommendation (AGENTS.md principle 3, tokeny rule 20).
- Priority is a word with a neutral badge, never an AI symbol, a gradient or a purple accent (tokeny rule 20, audit step 2).
- Actions go only through the allowed transitions (Copilot spec A14); the same card shows the same status everywhere (the answer and the saved list share one status, **P**).
- A fallback is an information state, not an error: the rule-based insights still work (B3.24).
- The question field shows its length limit before the owner types past it (**P**: the field uses `maxLength`; a visible counter is not built).
- Metric definitions come from one source, the same as the dashboard (AGENTS.md metric rule).

## Retrofit (lesson 08): done

1. Phase 1: `Textarea` inside `Field`, with a hint for the limit and a `FieldError` when the server refuses the question (PR #137).
2. Phase 2: fallbacks as `Alert` (`info` or `warning`), the evidence as a table from the breakpoint and a list below it, `Disclosure` for the definitions (PR #144).
3. Phase 3: recommendation cards as `Card` with the priority and status `Badge`s; `ErrorState` for the saved list only (PR #158).
4. Phase 4: `SkeletonGroup` with a label for the page's loading state; the states sweep and the Storybook patterns (this PR).
