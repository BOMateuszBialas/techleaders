## Manual rules

<!-- uxproof:manual-start -->
Rules below are copied from the team's own design documents (sources in brackets). They are not new judgment calls; the owner decisions of 2026-10-24 are recorded in `.ai/design/tokeny.md` §8.

- Color roles: `--action` (red-600) is only for purchase actions ("Add to cart", "Checkout", "Place order", "Pay (demo)"). Prices, admin UI, icons, error text and dark frames never use it. Errors use `--destructive` (same red, told apart by form). [`.ai/design/tokeny.md` §1b, `docs/design-system.md` Avoid]
- Price text uses `--foreground`, not the action color. [`docs/design-system.md` Avoid]
- Admin buttons are never red; the admin primary action is `--primary` (neutral graphite). [`docs/design-system.md` Avoid]
- Demo data is always visibly marked with `--demo` / `--demo-surface`. [`.ai/design/tokeny.md` §1b, `AGENTS.md` principle 6]
- Disabled and hover states use state tokens, not opacity (`opacity-50`, `bg-primary/80`). [`docs/design-system.md` Avoid]
- Native elements first; color is never the only signal; errors via `FieldError` with `aria-describedby` / `aria-invalid`. [`docs/design-system.md` Accessibility]
- Radius: 8 px controls, 12 px cards, 4 px badges; pill only for the cart count. [`docs/design-system.md` Tokens and density]
- Targets: 44 px on a phone, 24 px everywhere. Store controls 40/44/48 px, admin 28/32/36 px on desktop. [`docs/design-system.md`]
- Errors the user must act on are shown next to the field, not in a toast. [`docs/design-system.md` Avoid]
- Icons: Tabler Icons (owner decision 5), not lucide. [`.ai/design/tokeny.md` §8]
- No gradients, no card shadows, no cards inside cards, no emoji as icons. [`docs/design-system.md` Avoid]
- Every new color pair is checked in both light and dark. [`docs/design-system.md` Tokens and density]
