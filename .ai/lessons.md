- **2026-10-19 — "No page scroll" is not "readable on a phone"; check table containers and the storefront too**:
  - The #56 mobile test checked only `scrollWidth` of admin pages. Meanwhile the storefront header pushed the cart link off-screen (page 485 px wide at 390). Copilot evidence tables hid the Value column inside their scroll container, because shadcn `TableCell` defaults to `whitespace-nowrap`.
  - At 390 px, also measure `[data-slot=table-container]` (`scrollWidth - clientWidth`) and the position of key controls.
  - Let text cells wrap (`whitespace-normal`, plus `wrap-anywhere` for long ids). Keep numbers `nowrap`.

- **2026-10-18 — Compare rules on raw values, not display values; one record shown twice needs shared client state (#63, #67)**: Copilot rule 5 compared percentages already rounded to 0.1%, so a store rate under 0.05% turned the rule off and products at the threshold flipped; a sort used `Number(fact.value)`, which is `NaN` for a formatted value. Rate facts now carry the unrounded `ratio` for rules (never sent to the model). Separately, a recommendation shown in the answer and in "Your recommendations" kept two independent client states, so the answer offered actions the server would refuse; a page-level context now shares the status each action returns. Also: `@google/genai`'s `response.text` getter writes `console.warn` past our logger; read the candidate's text parts instead (#65).

- **2026-10-18 — Shared e2e owner = shared Copilot question budget; agent-browser ignored an `sr-only` name suffix; heredoc Python on Windows hangs**: every Copilot e2e suite uses the global setup's owner session, so they share the per-owner limit of 10 questions per 10 minutes (#62); a second owner is impossible (exactly one owner). Each Copilot suite now calls `resetCopilotQuestionBudget()` (`e2e/support/copilot-budget.ts`) in `beforeAll`, which deletes the `copilot:ask:*` buckets of the throwaway e2e database; keep each suite under 10 questions. Separately, `find role button --name "Save: <title>"` did not match a button whose name came from visible text plus an `sr-only` span; an `aria-label` that starts with the visible text did. And in the agent's Bash tool, `python - <<'EOF'` (and a bare `cat >` before it) blocked on stdin until the 2-minute timeout: write the script with the Write tool and run it with `< /dev/null`.

- **2026-10-18 — A shared cleanup assumed every rate-limit window was at most an hour**: `DatabaseRateLimiter` deleted windows older than an hour whenever any key opened a new one, which silently reset the Copilot's 24 h LLM cap. Only an integration test that read the bucket after a real consume caught it. When a shared store gains a longer-lived key, re-check every cleanup and TTL that touches it; the limiter now refuses windows longer than its cleanup keeps.
- **2026-10-18 — Gemini free tier: 2.5 models are closed to new keys, 3 Flash thinks slowly by default**: the model list still shows `gemini-2.5-flash`, but new keys must use a 3.x Flash model, which thinks at a high level by default and missed a 20 s attempt timeout; `thinkingLevel: LOW` fixed it. A real-key smoke test also showed the model citing numbers in `reasoning` without citing their fact: grounding rejected it correctly, and spelling the rule out in the prompt made the retry pass. Smoke-test a prompt against the real model before calling the grounding too strict.

- **2026-10-17 — A production build evaluates a module once per server layer, so a per-evaluation `globalThis` cache key ping-pongs (#57)**: `container.ts` stamped its cached container with a per-evaluation `Symbol` (for dev hot reload, #35). In `next start`, route handlers and pages each evaluate their own copy of the module, so every alternating request disposed the other layer's container (ORM and Better Auth pools) and rebuilt it; a request still in flight then failed, which surfaced as an intermittent Better Auth "Failed to get session" 500. A production build now uses one shared owner (`Symbol.for`), and the per-evaluation key applies only outside production. Tell-tale sign: a one-time init warning (Better Auth's low-entropy secret warning) logged on every page/route alternation. Better Auth log lines now carry a sanitized summary of the underlying error (class, code, constraint, cause; no driver message).

- **2026-10-17 — A branch stacked on a squash-merged PR: replay only its own commits**: `feat/demo-store-phase-2` was built on `feat/admin-orders-phase-1` (and later merged it in); once #50 was squash-merged, a plain rebase or merge of `origin/main` would replay or conflict on the already-landed Phase 1 commits. Keep a backup branch, `git reset --hard origin/main`, then `git cherry-pick` only the stacked branch's own commits (skip the merge commit), and check `git diff --stat origin/main` shows only the new phase. Re-run the whole gate afterwards: the other phases' tests (here the dashboard e2e) now run against the new code.

- **2026-10-17 — An e2e wait satisfied by the page you are leaving**: `purchase.e2e.test.ts` clicked a product link on the listing, then waited for "Add to cart", which the listing's own quick-add buttons already show; the next step ran mid-navigation and found only the header's "Search" button. It failed on `main` and on every CI run of #50, never locally (faster machine). After a navigating click, wait for the new URL (`waitForUrl`) and for text only the target page has.
- **2026-10-17 — Windows Python cannot open Git Bash's `/tmp`**: `python - <<EOF` with `open("/tmp/x.md")` failed (Python resolves `/tmp` on the current drive, not Git Bash's temp), and the following `gh issue edit --body-file /tmp/x.md` silently re-posted the unchanged body. Pass `$(cygpath -w /tmp/x.md)` to Python, or use the scratchpad with a Windows path, and chain with `&&`.
- **2026-10-17 — A server action refreshes the page itself after a no-write conflict**: `runAdminAction` refreshes the page only after a change; when a conflict means the page is out of date (a stale order status), the action calls `refresh()` itself so the page re-renders with the current state.
- **2026-10-17 — The e2e sign-in budget is spent: share the setup's owner session; a generic double-click selector can pay the order**: adding one `signInAsOwner` in a new suite pushed the run over Better Auth's 20 sign-ins per minute, and `admin.e2e.test.ts` (unchanged) failed with "Too many attempts". The global setup now signs in once over HTTP and provides `ownerSessionCookie`; a suite that needs any signed-in owner calls `useOwnerSession(browser)` (`e2e/support/sign-in.ts`) and spends no sign-in. Keep `signInAsOwner` for tests about sign-in itself. Separately, the checkout double-submit test clicked `main form button[type="submit"]` a second time; when the payment page had already loaded, that click confirmed the demo payment, so the test waited for a pay page that had become the confirmation. Scope repeat clicks to the form they mean (`form:has(#checkout-customerName)`).
- **2026-10-17 — `Intl` month abbreviations differ between ICU versions; bind instants as ISO strings in raw SQL**: `Intl.DateTimeFormat("en-GB", { month: "short" })` printed "Sept" on Node 24 where the test expected "Sep", so a label that a test, a README or the Copilot quotes would change with the runtime. `metric-period.ts` uses `Intl` only for time-zone arithmetic (numeric parts) and a fixed month list for text. In the metric SQL, instants are bound as `toISOString()` and cast with `?::timestamptz`, so no driver or session time-zone setting can shift a period boundary; the integration fixture puts orders exactly on both boundaries of the half-open range to prove it.
- **2026-10-16 — MikroORM driver exceptions carry the failed SQL with its parameters**: a `DriverException` message (and the pg `detail`) inlines the query values, so logging an unexpected order-insert error would have written the customer's name, email, address and the order reference to the log. Adapters that write personal data or secrets throw `sanitizeDatabaseError(operation, error)` instead (`packages/database/src/adapters/sanitize-database-error.ts`: operation, class, SQLSTATE, constraint only); application errors pass through. Do the same for any new adapter whose parameters are sensitive.
- **2026-10-16 — A generic `form button[type=submit]` selector hits the header search; a race can fail before the row lock**: in the checkout e2e, `click('form button[type="submit"]')` submitted the storefront header's search form (first in the DOM) instead of the checkout; scope selectors to `main` or use `clickRole`. In the last-unit race, the losing request often fails at the cart re-check (the winner already committed) rather than at the conditional `UPDATE`, so test the row-lock path by calling the repository directly and accept either conflict at the use-case level. Also: a stale cookie the page cannot rewrite needs an explicit one-click server action (`acceptCartChanges`), or a flow that compares cookie and page can loop forever.
- **2026-10-16 — A server action's `refresh()` keeps the URL the page was requested with; the e2e sign-in limit is shared**: after `history.replaceState` dropped `?notice=created`, a later save's `refresh()` still rendered the notice, so the admin notice now also hides itself on the next form submit (`retireRedirectNotice`). Separately, every e2e sign-in counts against Better Auth's limit of 20 per minute (no trusted IP header in tests): two extra sign-ins made `admin.e2e.test.ts` time out at sign-in. New e2e tests reuse the owner session (a trailing `describe` without `clearCookies`), and a second browser gets the owner's cookies with `BrowserSession.shareCookiesWith` instead of signing in. agent-browser tabs were unreliable here (`tab close <label>` did not find the tab).
- **2026-10-16 — A Server Component cannot fix a cookie; shell-quoted Python can eat escapes**: the cart page corrects a stale cart (sold-out line, quantity above stock) in what it renders, but cookies can be set only in Server Actions and Route Handlers, so the stored cookie stays stale until the next cart action; design read paths to be idempotent over a stale cookie and say so in the UI copy. Separately, a Python edit run through a Bash heredoc turned the TypeScript escape `\n` inside a string into a real newline (a syntax error in a test); write code that contains backslash escapes with the Edit/Write tools.
- **2026-10-16 — Write backslash-heavy test strings with the Write/Edit tool, then check them with `od -c`**: while adding search-escaping tests, doubled backslashes inside a shell heredoc piped to Python were collapsed on the way into the file, twice, so the expected pattern `"%100\\%%"` (escaped `%`) became `"%100\%%"`, which JavaScript reads as `"%100%%"` (a test that proves nothing). For strings with backslashes (LIKE patterns, regexes, Windows paths) use the Write or Edit tool, and confirm the bytes with `od -c` when a test about escaping passes on the first try.
- **2026-10-16 — Raw `em.execute` returns timestamps as strings; native `min` hides server field errors; never pipe a gate step into `tail`**: in the stock integration tests, `em.execute("select updated_at …")` gave a string, not a `Date` (MikroORM leaves raw rows unhydrated), so `.getTime()` threw; select `updated_at::text` and compare strings, or go through an entity. A number input with `min="0"` makes the browser block submitting `-1`, so the server's field error never shows (and an e2e test for it cannot pass); the stock panel form uses `noValidate` and keeps `min`/`step` for the spinner. Running `npm run typecheck 2>&1 | tail` inside an `&&` chain hid a failing workspace (the pipe's exit code is `tail`'s); `next build` caught it. Run gate steps without a pipe, or check `PIPESTATUS`.
- **2026-10-16 — Check validation rules against the seed data; a missing form field arrives as `""`**: the spec's `https:`-only image rule would have made every seeded product unsavable, because the seed stores local `/demo/…` paths; the rule now also accepts those paths. Before shipping an input rule, run it against the values the seed (and existing rows) already hold. Also, `readFormValues` turns a missing field into `""`, so a Zod `.default()` never fires for it: map `""` to `undefined` with `z.preprocess` when blank must mean the default.
- **2026-10-15 — MikroORM 7 exposes the PostgreSQL constraint name; e2e must wait for streamed admin content**: MikroORM's `DriverException` copies the `pg` error's own properties, so `error.code` (SQLSTATE, e.g. `23505`) and `error.constraint` (e.g. `categories_slug_unique`) are readable structurally; map them by name (`toCatalogWriteError`) instead of `instanceof` on exception classes. In e2e, admin pages render a static shell first and stream the form inside `<Suspense>`, so `fillLabel`/`clickRole` right after `open()` can miss the form: wait for text that only the streamed part renders. For a client error boundary, pass `retry` directly to `onClick` (no arrow), so a static render covers every function.
- **2026-10-15 — Repeated link names break `clickRole` in e2e; the test DB sorts with a byte collation**: once the storefront header and footer listed every category, a category name such as "Mice" appeared in three navigations, so e2e tests click a specific link by CSS selector (`BrowserSession.click('nav[aria-label="Categories"] a[href=…]')`). Also, `orderBy: { name: "asc" }` in the Testcontainers PostgreSQL put "[E2E] Draft Vortex mouse" before "[E2E] Draft keyboard" (uppercase first), so assert sort order on names whose case does not differ, or document the collation in the test.
- **2026-10-15 — Dev server kept a DI container from before the merge**: after #34 merged, a `next dev` started earlier showed "The catalog is temporarily unavailable" (`AwilixResolutionError: Could not resolve 'listCatalogCategoriesUseCase'`). The container is cached on `globalThis` to survive hot reloads, so it never saw the new registrations. `container.ts` now stamps the cache with a per-evaluation `Symbol`; a container from an older evaluation is disposed (pools closed) and rebuilt. When a page breaks only on a long-running dev server, suspect module-level or `globalThis` caches before the code.
- **2026-10-15 — `instanceof` on core errors fails across Next.js server chunks**: the storefront showed "catalog unavailable" instead of "not found" in e2e, but only after other pages had run. Next.js bundled `@commerceos/core` into more than one server chunk, and the container cached on `globalThis` kept use cases built from the first chunk's copy, so their `NotFoundError` failed `instanceof` in another chunk's loader. Match errors by their stable `code` (`hasAppErrorCode` / `isNotFoundError` in core). `apiHandler` follows the same rule since #36: it maps `CLIENT_ERROR_CODES` to statuses and reads `fieldErrors` structurally, so never reintroduce `instanceof` against an `AppError` subclass in the app. Reproduce such bugs by visiting another page first; a fresh server hides them.
- **2026-10-15 — Negated `toBe` on ORM objects can take seconds (flaky CI timeout)**: `expect(fresh.cradle.orm).not.toBe(orm)` made Vitest serialise the MikroORM instance. With 5 more entities that took 1.4 s locally and over 5 s in CI (test timeout on 3 of 5 runs), while `main` stayed fast. Compare identity with `===` and assert the boolean, the same rule as for cradle proxies. Profile a slow test step by step before guessing.
- **2026-10-15 — `betterAuth()` starts initialising as soon as it is built**: it kicks off a background database schema check. Unit tests stub `createAuth` (or point the pool at an unused port and end it); only integration tests build a real instance, after migrations.
- **2026-10-15 — Better Auth: `auth.api.*` skips the rate limit and the origin check**: both run only in the HTTP router (`auth.handler`). A server action calling `auth.api.signInEmail` would sign in with no brute-force limit. `server/auth/sign-in.ts` therefore posts through `auth.handler()` and copies the cookie with `parseSetCookieHeader` / `toCookieOptions`; `nextCookies()` does nothing on the router path. Also, Better Auth silently disables the origin check when `NODE_ENV=test` unless `advanced.disableOriginCheck: false` is set; we set it, and integration tests caught the difference.
- **2026-10-15 — `try/catch` around `headers()`/`connection()` breaks `next build`**: a route handler wrapped in `apiHandler` logged "During prerendering, `connection()` rejects…" as an unhandled route error at build time. Call `await connection()` before entering the try/catch (as `/api/health` and `adminApiHandler` do), or `unstable_rethrow(error)` in the catch.
- **2026-10-15 — `packages/app` scripts run as CommonJS under tsx**: the package has no `"type": "module"`, so top-level `await` fails in a `.ts` entry run by tsx. Use `run().then(...)` in CLI entry points, and keep the logic in an injectable, unit-tested `run*` function so the entry needs no coverage exclusion.
- **2026-10-15 — Better Auth 1.7 surprises (spike for the admin auth spec)**:
  - The rate limiter keys on `x-forwarded-for` by default, and a client can forge it when there is no proxy. Set `advanced.ipAddress.ipAddressHeaders: []` unless a trusted proxy overwrites a header; then production uses one shared `no-trusted-ip` bucket per path.
  - `disableSignUp` also blocks server-side `auth.api.signUpEmail`. Provision users with `$context.internalAdapter.createUser(user, { method: "admin" })` + `linkAccount` + `password.hash`, and revoke with `deleteUserSessions(userId)` (`deleteSessions` takes tokens).
  - The `Secure` flag and the `__Secure-` prefix follow the `baseURL` protocol, not `NODE_ENV`.
  - The instance checks the schema at init, so build it lazily at request time, never at import or prerender.
  - Details: `.ai/specs/implemented/2026-10-15-admin-authentication.md`, "Spike results".
- **2026-10-15 — `npx skills add` installs where Claude Code does not look**: skills land in `~/.agents/skills/`, but Claude Code reads `~/.claude/skills/` and `.claude/skills/`. Copy the skill there, plus any skill it delegates to (`grill-me` only calls `grilling`).
- **2026-10-15 — Python on Windows writes CRLF**: `open(p, "w")` in text mode turned a spec into CRLF. The index stayed LF, but the working tree showed a phantom change that blocked `git switch`. Pass `newline="\n"` when a script rewrites repo files.

- **2026-10-14 — CRLF checkouts break `format:check` on Windows**: Git for Windows defaults to `core.autocrlf=true`, so a checkout had CRLF line endings and `npm run format:check` (Prettier `endOfLine: lf`) failed on about 85 files locally, while CI on Linux passed the same commit. `.gitattributes` now has `* text=auto eol=lf`, which pins every checkout to LF; the index was already LF. Existing clones keep CRLF files until re-checkout. Fix one with `git rm --cached -r . && git reset --hard` (commit or stash work first). When a local gate fails but CI passes, check line endings (`git ls-files --eol`) before blaming the code.

- **2026-10-13 — agent-browser daemon keeps stdout open**: the first command of a session starts a background daemon that inherits the CLI's stdout pipe, so `execFile` (which resolves on stdio *close*) hung until its 30 s timeout, and a catch that read `error.stdout` silently swallowed the timeout. Run the CLI with `spawn` and resolve on the `exit` event (`packages/app/e2e/support/agent-browser.ts`); never treat a timeout as a normal result.
- **2026-10-13 — Vitest alias `"@/"` as an object key**: it did not resolve `@/…` imports inside real modules (only mocked ones), failing with "Cannot find package '@/server/logger'". Use the array form with a regex: `{ find: /^@\//, replacement: … }`.
- **2026-10-13 — Awilix cradle proxies in `expect`**: comparing objects whose fields are the cradle proxy with `toBe`/`not.toBe` can make Vitest walk the proxy and throw `AwilixResolutionError: Could not resolve 'size'`. Compare identity with `===` and assert the boolean.
- **2026-10-13 — MikroORM `checkConnection()` on a lazy ORM**: an ORM built with `new MikroORM(config)` (no `connect()`) reports `{ ok: false, reason: "Connection not established" }` from `checkConnection()` until a query opens the pool, so `/api/health` was always "down". Health checks run `em.fork().execute("select 1")`, which connects on demand. Integration tests must also exercise the ORM the way the app builds it, not only via `MikroORM.init`.
- **2026-10-13 — ESLint flat config `no-restricted-imports`**: a later config object with the same rule *replaces* (does not merge) the options of an earlier one for overlapping files. Keep package-boundary blocks on non-overlapping globs (`packages/<name>/src/**`) and carve out exceptions with `ignores`.
- **2026-10-13 — Docker on the dev machine needs Virtual Machine Platform**: Docker Desktop starts, but the API returns HTTP 500 because "Virtual Machine Platform not enabled / No virtualization available" (see `%LOCALAPPDATA%/Docker/log/host/com.docker.backend.exe.log`). It needs admin rights and a reboot to fix; the alternative is a hosted Postgres via `DATABASE_URL`.
- **2026-10-13 — MikroORM 7 specifics**: use `defineEntity` + `p.*` builders (no decorators). `new MikroORM(config)` is synchronous and connects lazily, so it works in the DI container and in unit tests without a DB. `orm.schema.getCreateSchemaSQL()` generates DDL with no DB connection. Migrator and seeder are extensions (`extensions: [Migrator, SeedManager]`) available as `orm.migrator` / `orm.seeder`.
- **2026-10-13 — Next 16 Cache Components**: request-time data (DB, health) must call `await connection()` and sit inside `<Suspense>`. The `react-hooks/error-boundaries` lint rule forbids building JSX inside try/catch, so load data in a helper and render outside it.
- **2026-10-13 — shadcn/ui 4 uses the `cn` package**: `shadcn init` (style `base-nova`) installs `cn` (by shadcn, repo shadcn-ui/cn) instead of `clsx` + `tailwind-merge`, plus `@base-ui/react`. It is legitimate, not a typosquat.
- **2026-10-13 — Monorepo gitignore**: create-next-app patterns are root-anchored (`/.next/`, `/node_modules`). In the monorepo they must be unanchored (`.next/`) or `packages/app/.next` gets tracked.
- **2026-10-13 — Writing many files at once**: one long Bash chain with several heredocs failed to parse as a whole (nothing ran). Use the Write tool per file instead.
