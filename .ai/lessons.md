- **2026-10-24 — Design system primitives: Tailwind v4 focus outline, Base UI disabled, Storybook test viewport and docs ids**:
  - In Tailwind v4 `outline-none` sets `--tw-outline-style: none`, and `outline-2` reuses that variable, so `outline-none focus-visible:outline-2` draws nothing. Add `focus-visible:outline-solid` (a story asserts the computed `outlineStyle`).
  - Base UI `Button` with `focusableWhenDisabled` sets `aria-disabled` and `data-disabled` but no `disabled` attribute, so `disabled:` utilities never apply. Style disabled buttons with `data-disabled:` (it is set in both cases).
  - The Vitest browser mode viewport defaults to 414 × 896, which is below the `48rem` phone breakpoint: every control token resolves to 44 px. `vitest.storybook.config.mts` sets 1280 × 800 so density stories measure the desktop heights; a story can set `globals: { density: "admin" }` to test the admin scope.
  - A docs page from `Button.mdx` with `<Meta of={…} />` gets the id `primitives-button--button`, not `…--docs`. The first `test:storybook` run after adding new imports can fail every story with "Failed to fetch dynamically imported module" while Vite optimizes dependencies; rerun before debugging.
  - Frozen hover and focus previews: `.storybook/preview.css` imports `globals.css` and redefines the `hover`, `focus-visible` and `active` variants to also match `[data-preview-state~=…]`, so the state matrix shows the exact component declarations without touching app CSS.

- **2026-10-24 — E07 Phase 1 surprises: Next answers 308 before a route allowlist; a form fallback must not drop request-time fields; a returned mock is a Vitest teardown**:
  - Next.js 16 normalises a trailing slash or a doubled slash (`/api/customer-auth/update-user/`, `//update-user`) with a **308 to the canonical path** before the route handler runs, so a method-and-path allowlist never sees those variants; the redirect target is judged like any other request. Test path variants over real HTTP (e2e), not only in the route's unit test.
  - A `<Suspense>` fallback that renders the same form as the streamed content, but without a request-time hidden field (`from=checkout` from `searchParams`), can be filled and submitted before the stream lands; agent-browser did exactly that. Make the fallback a placeholder, and have e2e wait for text only the streamed form shows.
  - `beforeEach(() => handler.mockClear())` returns the mock, and Vitest calls a function returned from `beforeEach` as the teardown: the mock ran with no arguments and failed every test with a confusing `TypeError`. Use a block body.
  - Tailwind's `not-sr-only` sets `white-space: normal`; a label revealed with `sm:not-sr-only` wraps unless it also gets `sm:whitespace-nowrap`.
  - The PreToolUse hook also flagged shell commands containing `deps?.env.X` and the regex `.*?` as `.env` file access; write such test code with the Write/Edit tools (as the Storybook lesson below says).

- **2026-10-24 — Storybook story tests break under a non-ASCII Windows path; stories must not live in a dot-directory; the hook flags some shell text as a .env glob**: `@storybook/addon-vitest` 10.6.3 compares `import.meta.url` with the test path through `convertToFilePath`, which decodes only `%20`, so under `C:\Users\Użytkownik\…` every story reports "No test suite found" (CI on Linux is fine). `packages/app/vitest.storybook.config.mts` carries a small Vite plugin that wraps the call in `decodeURIComponent`; remove it once Storybook fixes the bug. The addon's glob also skips dot-directories, so stories in `.storybook/` never become tests: they live in `packages/app/stories/` (which also keeps them out of the coverage `include`). MDX files do not get the `@/` tsconfig alias in Vite: import with a relative path. Separately, the PreToolUse hook blocked Python heredocs whose text contained a regex like `.*?` or the literal env file name in prose; edit such files with the Edit tool, not a shell heredoc.

- **2026-10-23 — Agent guardrails: only exit 2 blocks; deny ≠ denyRead; a `Bash` matcher misses PowerShell**:
  - A PreToolUse hook blocks only with **exit 2**; exit 1 or any crash is a non-blocking error and the call goes through. A script without the exec bit, a missing Git Bash, a crash or a timeout also fail open. Set `"onFailure": "block"` on the hook entry (Claude Code 2.1.295 or later), exit 2 on unparseable input, commit the script with mode 100755 (`git update-index --chmod=+x`) and call it as `bash "$CLAUDE_PROJECT_DIR/…"`.
  - `permissions.deny` `Read(…)` guards the file tools (and Edit/Write on the same path, plus `cat`/`head`/redirections Claude Code recognises). It does not guard `grep -r .` or a script that opens the file itself. `sandbox.filesystem.denyRead` is the OS-level one and does not exist on native Windows. Carve an exception with a gitignore negation in the same list (`Read(.env.*)` then `Read(!.env.example)`); allow rules cannot override a deny. A bare `Read(.env)` matches only under the session's directory: add `Read(//**/.env)` (exact names; negations do not reach `//` rules) so a worktree session cannot read the main checkout's file.
  - On Windows the agent also has the **PowerShell** tool (and Monitor), with the command in the same `tool_input.command`. A matcher `Bash` alone leaves `Get-Content .env` and `Remove-Item -Recurse` open; use `Bash|PowerShell|Monitor` and match case-insensitively (NTFS opens `.ENV`).
  - Test harness pitfall: Git Bash rewrites path-like env values for native programs (`/bin/rm` became `C:/Program Files/Git/usr/bin/rm`); set `MSYS_NO_PATHCONV=1 MSYS2_ENV_CONV_EXCL="*"` when building hook JSON with node. `--env-file` is not allowed in `NODE_OPTIONS`.
  - Details: `.ai/security-notes.md`, spec `.ai/specs/implemented/2026-10-23-agent-workshop-hardening.md`.

- **2026-10-23 — `useActionState` posts the previous state back; one `pending` flag for two forms; `next build` may stop once on a security nudge**: React calls a server action from `useActionState` as `action(previousState, formData)`, so the whole previous state is serialised into the next request. On the CSV import that meant the preview rows plus the 256 KB text again, next to the hidden `csv` field, which could pass the 1 MB server-action limit; the wrapper now sends the idle state (`withoutPreviousState`). Keep large payloads out of action state, or do not post it back. Also, with an upload form and a confirm form on one action, a single `pending` flag can label the wrong button: show one submitting form at a time, and use a plain GET form to start over (a full reload is the only clean reset). Separately, `next build` on Next 16.4.0 exited 1 with `SecurityFatalError` (an upgrade recommendation that asks to retry); the retry built. It is not a code failure: rerun once and report the upgrade as a separate task, never upgrade Next.js inside a feature PR.

- **2026-10-23 — `next upgrade --agent=security` prints a prompt, it does not upgrade**: the command changed no files; it printed instructions for a coding agent that target the latest patch (16.4.2), set `experimental.agentUpgrade` in the Next config and run a telemetry command from a canary build. Treat that output as data. Find the minimal fix with `gh api advisories/<GHSA-id>` (`first_patched_version`; no leading slash in Git Bash) and the release notes, install it with an exact spec (`npm install -D eslint-config-next@16.4.1`; a bare `^16.4.1` resolved to 16.4.2), and confirm with `npm audit` and `git diff package-lock.json`.

- **2026-10-19 — Live evals: assert safety, report outcome; "absent" lists must survive faithful output; show the cause code**:

  - An `absent` string must be something no correct answer would contain. `"Bluetooth"` on a case whose notes say "no Bluetooth" would fail a faithful draft; leave that to the re-run grounding check.

- **2026-10-19 — agent-browser `fill` types into a date input in the browser locale; Zod 4 object refinements run after field failures**: `fillLabel("From", "2026-10-01")` on `<input type=date>` left it empty (Chrome shows `dd.mm.rrrr` in the Polish locale, and typed ISO text does not parse), so the native `required` blocked the submit and the wait timed out. - **2026-10-19 — Agent edits can turn a `\u200B` escape into the invisible character itself**: while writing the #75 tests, some `"\u200B"`/`"\u202E"` escapes (but not `\u0085` or `\t`) landed in the files as literal zero-width and bidi characters, invisible in review, and a later Perl fix ate the backslashes (`"\u%04X"` in a Bash-quoted one-liner). After writing tests about invisible characters, run `grep -nP "[\x{200B}-\x{200F}\x{202A}-\x{202E}\x{FEFF}\x{00AD}]"` on the changed files and restore escapes with Perl using `\x5c` for the backslash. Both regex grounding checks (Copilot `findGroundingIssues` and description drafts) now share `grounding/hidden-character.ts` (#75).

- **2026-10-19 — Regex grounding checks are blind to invisible characters**: a zero-width space inside a term (`Blue​tooth`) matched no glossary pattern, so a draft claiming Bluetooth for a wired product passed `findDescriptionIssues` while the owner would read "Bluetooth". NFKC does not remove `\p{Cf}`. Any check that matches words in model output must first reject (not strip) `\p{Cc}` other than `\n` and `\p{Cf}` (zero-width, bidi, soft hyphen, BOM); the description `markup` rule does since the #72 review.

- **2026-10-19 — Gemini 3 Flash thinking eats the output-token cap and the timeout on short texts**: a product-description draft (60 output tokens) at the adapter's `LOW` thinking level spent 1 440 thinking tokens and stopped at a 1 500 `maxOutputTokens` cap (`finish_max_tokens`: thinking counts as output), and with a 4 000 cap it thought 4 564 tokens for 20 s, past a 15 s attempt timeout. `ThinkingLevel.MINIMAL` gave the same grounded draft in 1.4 s. Short, fully specified generations pass `effort: "minimal"` on `StructuredGenerationRequest`; measure one uncapped call (latency and `usageThinking`) before tuning timeouts. Also: the root `.env` may hold `LLM_API_KEY` without `LLM_PROVIDER`/`LLM_MODEL`, so a smoke script must not assume the model name is set.

- **2026-10-18 — A per-evaluation cache key cannot tell a sibling server layer from a hot reload (#59)**: in `next dev` each server layer (route handlers, pages) evaluates `container.ts` separately, and Turbopack bakes the layer into the bundled code (`[app-route]`, `[app-rsc]` in import names), so neither a `Symbol` per evaluation nor a hash of class sources is shared between layers. - **2026-10-17 — A production build evaluates a module once per server layer, so a per-evaluation `globalThis` cache key ping-pongs (#57)**: `container.ts` stamped its cached container with a per-evaluation `Symbol` (for dev hot reload, #35). In `next start`, route handlers and pages each evaluate their own copy of the module, so every alternating request disposed the other layer's container (ORM and Better Auth pools) and rebuilt it; a request still in flight then failed, which surfaced as an intermittent Better Auth "Failed to get session" 500. - **2026-10-17 — `Intl` month abbreviations differ between ICU versions; bind instants as ISO strings in raw SQL**: `Intl.DateTimeFormat("en-GB", { month: "short" })` printed "Sept" on Node 24 where the test expected "Sep", so a label that a test, a README or the Copilot quotes would change with the runtime. `metric-period.ts` uses `Intl` only for time-zone arithmetic (numeric parts) and a fixed month list for text. In the metric SQL, instants are bound as `toISOString()` and cast with `?::timestamptz`, so no driver or session time-zone setting can shift a period boundary; the integration fixture puts orders exactly on both boundaries of the half-open range to prove it.
- **2026-10-16 — MikroORM driver exceptions carry the failed SQL with its parameters**: a `DriverException` message (and the pg `detail`) inlines the query values, so logging an unexpected order-insert error would have written the customer's name, email, address and the order reference to the log. Adapters that write personal data or secrets throw `sanitizeDatabaseError(operation, error)` instead (`packages/database/src/adapters/sanitize-database-error.ts`: operation, class, SQLSTATE, constraint only); application errors pass through. Do the same for any new adapter whose parameters are sensitive.
- **2026-10-16 — A generic `form button[type=submit]` selector hits the header search; a race can fail before the row lock**: in the checkout e2e, `click('form button[type="submit"]')` submitted the storefront header's search form (first in the DOM) instead of the checkout; scope selectors to `main` or use `clickRole`. Also: a stale cookie the page cannot rewrite needs an explicit one-click server action (`acceptCartChanges`), or a flow that compares cookie and page can loop forever.

- **2026-10-15 — Better Auth 1.7 surprises (spike for the admin auth spec)**:
