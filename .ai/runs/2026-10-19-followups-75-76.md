# Run: follow-ups #75 and #76 (AI description drafts and Copilot grounding)

- Date: 2026-10-19
- Branch / worktree: `fix/followups-75-76`, `../wt-75-76` (from `origin/main` f793905)
- Mode: autonomous (delegated agent); one PR for both issues

## Goal

- #75: check whether the Copilot's `findGroundingIssues` has the invisible / control character blind spot that #72 fixed for description drafts, and fix it the same way.
- #76: four minor review points from #72/#74: "for Switch" without a verb, Undo after edits, guidance in the error colour, a test-only re-export of `LLM_DAILY_*`.

## Steps

1. Wrote failing unit tests first: a zero-width space inside "drove" hid a causal claim, and C1, bidi, soft hyphen, BOM, tab and DEL all passed `findGroundingIssues` (8 tests red on `main`).
2. Moved the description drafts' `HIDDEN_CHARACTER` rule to `packages/ai/src/grounding/hidden-character.ts` and used it in both checks. The Copilot reports a new `hidden_character` issue (retry, then the rule-based fallback). The check runs after catalog product names are blanked, because an owner's name (an emoji joiner) is not model text and rule answers quote it too. Added the eval case `hidden-character` (fails without the fix) and a row in the Copilot spec's grounding table.
3. #76 "for Switch": added glossary patterns for "for Switch" at the end of a clause and Switch next to another platform ("PC or Switch"), keeping "for switch changes" a keyboard part. Glossary version bumped to `.2`, eval case `invented-platform-without-verb`, spec row updated.
4. #76 Undo: the applied state now keeps the draft text; Undo refuses (guidance message, nothing overwritten) when the field differs from the draft (edited) or the field's `defaultValue` is the draft (saved). An e2e test pins that a successful Save re-renders the textarea with the saved text as its default, which the check relies on.
5. #76 colour: messages carry a `tone`; guidance (too little input, not configured, a field message, Undo unavailable) is muted, failures and limits stay `text-destructive`.
6. #76 re-export: removed from `generate-answer.ts`; the test imports `llm/llm-daily-cap.ts`. Refactor only, so no behaviour test.

## Decisions

- The live hiding of Undo (on typing) was not added: it needs an effect listening to an uncontrolled textarea in the hook-free view, outside unit coverage. The guard at click time removes the defect (silent loss of edits) instead.
- `risk-medium`: the grounding change only rejects more model output (fallback is the rule-based answer); the UI change is local to the draft panel.

See the PR for the gate results. No real LLM calls were made.
