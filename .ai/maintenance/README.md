# Maintenance audits

Each file here is one knowledge audit of the repository, named `YYYY-MM-DD-audit.md`.

- An audit is a dated snapshot. Do not edit it after it is written, not even to tick a finding or record a decision. Its findings are the state on its date.
- The next audit is a new file with a new date. It may cite the previous one to show what was fixed, what is still open, and what is new.
- Findings are classified as fix now, owner decision, or later. Fixes happen in their own pull requests, not in the audit file.
