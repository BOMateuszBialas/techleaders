# 2026-10-15 — `instanceof` on core errors fails across Next.js server chunks

The storefront showed "catalog unavailable" instead of "not found" in e2e, but only after other pages had run. Next.js bundled `@commerceos/core` into more than one server chunk, and the container cached on `globalThis` kept use cases built from the first chunk's copy, so their `NotFoundError` failed `instanceof` in another chunk's loader. Match errors by their stable `code` (`hasAppErrorCode` / `isNotFoundError` in core). `apiHandler` follows the same rule since #36: it maps `CLIENT_ERROR_CODES` to statuses and reads `fieldErrors` structurally, so never reintroduce `instanceof` against an `AppError` subclass in the app. Reproduce such bugs by visiting another page first; a fresh server hides them.
