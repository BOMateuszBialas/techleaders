# 2026-10-16 — Raw `em.execute` returns timestamps as strings; native `min` hides server field errors; never pipe a gate step into `tail`

In the stock integration tests, `em.execute("select updated_at …")` gave a string, not a `Date` (MikroORM leaves raw rows unhydrated), so `.getTime()` threw; select `updated_at::text` and compare strings, or go through an entity. A number input with `min="0"` makes the browser block submitting `-1`, so the server's field error never shows (and an e2e test for it cannot pass); the stock panel form uses `noValidate` and keeps `min`/`step` for the spinner. Running `npm run typecheck 2>&1 | tail` inside an `&&` chain hid a failing workspace (the pipe's exit code is `tail`'s); `next build` caught it. Run gate steps without a pipe, or check `PIPESTATUS`.
