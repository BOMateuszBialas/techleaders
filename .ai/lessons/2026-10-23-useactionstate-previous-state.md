# 2026-10-23 — `useActionState` posts the previous state back; one `pending` flag for two forms; `next build` may stop once on a security nudge

React calls a server action from `useActionState` as `action(previousState, formData)`, so the whole previous state is serialised into the next request. On the CSV import that meant the preview rows plus the 256 KB text again, next to the hidden `csv` field, which could pass the 1 MB server-action limit; the wrapper now sends the idle state (`withoutPreviousState`). Keep large payloads out of action state, or do not post it back. Also, with an upload form and a confirm form on one action, a single `pending` flag can label the wrong button: show one submitting form at a time, and use a plain GET form to start over (a full reload is the only clean reset). Separately, `next build` on Next 16.4.0 exited 1 with `SecurityFatalError` (an upgrade recommendation that asks to retry); the retry built. It is not a code failure: rerun once and report the upgrade as a separate task, never upgrade Next.js inside a feature PR.
